# Agent Note: Xiaowei federated tool capabilities

Status: proposed

[English](2026-08-29-xiaowei-federated-tool-capabilities.md) | 中文

## 问题

Xiaowei 本地和云端工作区需要暴露相同工具，但不能让一个 Host（主机）代另一个 Host 执行、存储状态或施加副作用。通用远程工具路径会模糊位置归属、削弱授权，并使失败无法与本地执行区分。静态注册本身也不能证明两个组装后的 Host 执行相同的 `web_search` 约定。

## 提案

围绕共享 manifest（元数据清单）约定定义 federated tool capability（联邦工具能力）：精确工具名、输入和结果 schema、render intent（渲染意图）、error taxonomy（错误分类）以及 risk classification（风险分类）。每个 Host 拥有其位置的执行、运行时状态、数据、凭据和副作用。

跨 Host 操作只能使用窄范围 typed relay（类型化中继）。中继标明目标位置、限制字段，并明确授权、序列化、取消和错误语义。不提供通用 remote tool bus（远程工具总线）、动态转发或无类型代理。

对于缺失、不支持、含糊、未授权或未通过 parity（对等一致性）的位置，路由快速失败。manifest/parity 门禁在组装前比较共享约定。`web_search` 是精确组装回归：两个 Host 必须暴露相同约定，并通过成功与失败的执行检查。

验收将无密钥 source（源代码）和组装证据与安装客户端、发布证据分开记录。真实安装和已发布表面被观察到之前，不声称后两类证据。

## 考虑过的替代方案

**通用远程工具总线。** 否决，因为任意转发会跨 Host 转移执行和授权决策，并使副作用难以归属。

**重复定义彼此独立的工具。** 否决，因为 schema、渲染、错误和风险漂移只能在客户端分化后才发现；manifest/parity 门禁将共享字段显式化。

**客户端回退到另一个 Host。** 否决，因为不可用或未授权的位置必须快速失败，不能静默改变数据归属或执行位置。

## 验收标准

- 无密钥 source 检查比较共享 manifest 字段，并拒绝每一种 parity 不一致。
- 组装检查证明类型化中继限制、Host 本地的执行/状态/数据/副作用归属和快速失败路由。
- 精确的 `web_search` 回归在本地和云端 Host 执行匹配的成功与失败行为。
- 报告区分无密钥 source/组装检查与安装客户端、发布证据，不作未观察到的安装或生产声明。

## 风险

共享 manifest 字段可能过度限制真正的 Host 特有行为；这类行为必须成为独立能力，或成为显式类型化的 Host 归属字段，不能使用隐式例外。中继定义会增加序列化和取消维护成本。source 和组装检查仍不能证明安装态发布，因此发布提升需要独立的真实客户端证据。
