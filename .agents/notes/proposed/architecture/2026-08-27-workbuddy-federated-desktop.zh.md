# Agent Note: WorkBuddy 式小薇联邦桌面端

Status: proposed

[English](2026-08-27-workbuddy-federated-desktop.md) | 中文

## Problem

全局本机或云端连接会用一个受限 Host 替换完整云端产品、重载渲染器，并使已有能力看起来被删除。同时将通用 dsh CLI 生产依赖闭包放入该 Host，会让已安装应用体积增加一倍以上，并引入与设备 Workspace 执行无关的依赖。

## Proposal

小薇桌面端将保留一套完整渲染器，并联邦一个生产 Host 与一个按需启动的回环设备 Host。侧边栏将对本机和云端 Workspace 分组，携带位置的桌面端标识会使每个 Workspace、Session、事件、审批、产物、子智能体和工作流操作始终留在其归属 Host。本机故障不会中断云端分组。

Electron 只会把所选目录的规范路径交给回环 Host。独立的云端副本确认操作会继续使用有界、账号归属的导入协议。选择、恢复和普通本机执行绝不会上传目录。

设备 Host 将通过同一 UI 提供常规本机 Worker 能力。文件系统工具继续强制 Workspace 规范路径限制；Shell 和子进程执行使用现有的按 Session 沙盒策略与审批流程，委托工作继承 Session 位置、cwd 和权限状态。本机 Skill 安装只发布到设备运行时 home 下，云端安装继续在生产 Host 上按账号隔离。

已登录的本机 Session 将使用账号平台模型，但不会把 Agent Loop 迁移到生产 Host。设备 Host 组装每次模型请求，并接收流式文本、推理、工具调用、用量与结束帧；工具在本机执行，结果记入本机日志后再随下一次模型请求发送。Electron 通过已有的云端认证连接中继该流，因此账号 Bearer 不进入设备子进程；生产 Host 只从 Bearer 解析归属，预留和结算同一钱包，并继续保管上游模型密钥。推理路由拒绝本机 Session、Workspace、owner、路径与文件引用字段，也不会创建云端 Session 或 Workspace。

一个专用私有设备运行时应用将维护精确的生产依赖清单与固定 Cordis 组合。桌面端打包将部署该应用，而不是 `@deepseek-ai/dsh`；它会排除浏览器渲染器和云端专用包，并且只解包必须使用真实文件的原生模块。每个平台的脚本会向运行时构建器声明产物的操作系统与 CPU 架构；构建器会要求对应的原生包、拒绝构建主机与错误目标的变体，并把目标记录到逐包体积账本中。包体验证还会拒绝相对已验收 0.3.16 基线增加超过 35 MiB 的 macOS arm64 DMG。

连接偏好将不再表示全局执行归属。0.3.16 安装将从云端产品视图启动；0.3.17 和 0.3.18 偏好只迁移最后选中的资源位置。已有设备运行时数据保留在原位，不会被上传或删除。

## Alternatives considered

**保留全局执行环境开关。** 不采用，因为一个 Host 会替换另一个 Host 的 Workspace 和 Session 清单、重载完整渲染器，并把能力差异变成产品降级的观感。

**只扩大受限本机 profile 的工具列表，不做 Host 联邦。** 不采用，因为这能改善本机任务，但在选中本机时仍会隐藏用户的云端 Workspace 和账号产品。

**继续打包通用 dsh CLI。** 不采用，因为其清单有意锚定所有已发布 profile 和 provider，依赖过滤无法产生设备专用运行时。

**根据构建主机推断安装包运行时目标。** 不采用，因为同一台 macOS arm64 发布机还会产出 macOS x64、Linux x64 与 Windows x64 安装包。主机推断会把无法使用的原生二进制静默放入所有交叉构建产物。

**上传每个所选目录。** 不采用，因为副本会引入传输限制、重复存储、丢失外部编辑同步，并在没有独立用户操作的情况下改变执行位置。

**将整个本机提示转发给云端 `session.prompt`。** 不采用，因为云端 Agent Loop 会取得工具执行权，无法安全访问原始目录，也无法证明 Shell、Skill、审批与产物效果留在设备。

**将分配的平台模型密钥复制到设备运行时。** 不采用，因为长期上游密钥会逃离服务端撤销、账号隔离、钱包约束与静态密钥控制。因此由 Electron 中继已认证的推理流。

**要求每个本机 Workspace 都另行配置用户模型密钥。** 作为自定义提供方路径仍保留，但不作为已登录状态的默认方案，因为它会让注册模型和赠送余额无法用于产品主要的本机执行流程。

## Acceptance criteria

本提案转为 implemented 之前，已批准的[功能规格](../../../../docs/specs/xiaowei/local-workspace-environment.zh.md)必须为每个验收 ID 提供仓库证据，其中包括已安装客户端与包体证据。

## Risks

联邦两路可变 Host 事件流需要位置安全的标识与穷尽方法路由；缺失的分类必须拒绝执行，不得猜测。推理中继会有意将模型可见对话与工具 schema 发给生产 Host，因此 UI 与文档必须将其与上传 Workspace 副本区分。恢复完整本机 Worker 会增加受信任的设备进程和原生依赖集。包体预算可能要求比通用 base bundle 更小的固定组合，而不是只过滤 manifest。
