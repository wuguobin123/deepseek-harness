# Agent Note: 将产品客户端固定为中文和浅色模式

Status: implemented

[English](2026-08-24-fixed-chinese-light-client.md) | 中文

## 问题

产品设置页提供了 Language 和 Appearance 选项，但该客户端只以中文浅色展示形态交付。这些控件还使浏览器语言、操作系统配色、Host settings 与桌面端 `localStorage` 成为启动时相互竞争的输入，因此遗留偏好可能覆盖预期的产品展示形态，或造成首屏不一致。

## 决策

发布的 locale 客户端以 `zh` 启动，设置 `<html lang="zh-CN">`，且不在 `settings.general.item` 中注册 `language` 项，也不注册 Host `locale.preference` schema。浏览器语言与已存储的 locale 分节不参与产品激活。

共享客户端与 Electron 账户外壳中由产品拥有的品牌名称、启动状态、标签、操作、状态、空态、确认文案和无障碍名称全部解析为中文。权限预设把稳定协议值映射为“只读”“工作区写入”和“完全访问”；`/permission` 参数与持久化预设 id 保持不变。模型名、提供方名称、工具名、协议标识、命令、路径、API 地址、文件格式，以及用户、模型、Host 或第三方提供的文本保持原文，客户端不做启发式翻译。

发布的主题客户端与 Host 引导代码以 `light` 启动，不注册 `appearance` 项或 Host `ui-theme.preference` schema，也不读取桌面端的 `dsh.theme` 键。桌面端预绘制会在 React 挂载前写入浅色配色，与后续 ThemeRuntime 快照保持一致。

LocaleRuntime 与 ThemeRuntime 保留供测试和扩展组合使用的编程式切换与注册表 API。发布的客户端在不带 settings scope 的情况下构造这两个运行时，因此这些 API 仅在进程内生效。英文字典与深色 token 调色板继续作为扩展与回落资产提供；它们不是产品设置。

## 验证

包组装测试断言中文与浅色快照，并断言 General 设置中不存在 `language` 和 `appearance` occupant。权限、对话、轨迹与组件测试固定中文标签，同时验证提交命令仍使用机器值。Host 测试断言两项 schema 均未注册，且每次主题引导都嵌入 `light`。桌面端预绘制测试预置遗留深色存储与操作系统深色偏好，随后验证系统不会读取这两个输入，并保持文档为浅色。生成的客户端 slot 目录不包含两个被移除的 occupant。

## 曾考虑的替代方案

**保留控件，只修改默认值。** 既有 Host 或浏览器值仍会覆盖默认值，用户也能让产品回到不受支持的展示形态。

**只在 Electron 外壳中隐藏控件。** Electron 挂载的是贡献这些设置行的共享 Web 客户端插件，因此只删除桌面端组件不会改变实际设置页，还会使 Web 组合与桌面端不一致。

**删除双语字典与深色调色板。** 运行时扩展、回落查找、语法展示和测试仍使用这些资产。删除产品选项不要求删除底层注册表能力。

## 后果

General 设置分节只包含其余可配置行。无论浏览器 locale、操作系统主题或遗留偏好数据如何，Web 与 Electron 启动时都使用中文产品文案和浅色首屏。外部原文仍可包含英文，因为翻译模型输出、名称、标识、诊断或数据会破坏来源含义。产品用户不再拥有语言与主题选择；重新引入任一选项都需要新的产品决策，以及只采用一个权威值来源的启动路径。
