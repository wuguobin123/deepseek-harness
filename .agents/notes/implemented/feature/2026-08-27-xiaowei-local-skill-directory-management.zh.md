# Agent Note: 小薇本地 Skill 目录管理

Status: implemented

[English](2026-08-27-xiaowei-local-skill-directory-management.md) | 中文

## Problem

桌面端当前提供给模型的 `skill_install` 工具只写入 `SKILL.md`。依赖脚本、模板、示例或其他嵌套资源的 Skill 因此看似已经安装，却无法执行完整工作流。桌面端也没有持久清单，用户无法独立于当前 Session 的生效目录查看正式本地运行时中有哪些 Skill。

## Decision

小薇桌面端提供原生目录导入器和可见的设置清单。主进程打开操作系统目录选择器，不把源路径或目标路径交给渲染进程。安装目标固定在正式 `userData/local-runtime/skills` 根目录下，本地内容不会上传。

导入器使用标准 YAML 解析器校验根目录 `SKILL.md`，复制有数量和字节上限的嵌套普通文件并排除版本库元数据，拒绝链接和特殊文件，在目标文件系统暂存后以原子重命名提交。相对名称、owner 执行状态和字节的摘要用于识别相同内容，使重复安装成为幂等操作。同名目录已有不同内容时返回冲突，不覆盖用户数据。

设置清单直接扫描已安装目录，不复用 `skill.list`，因为 `skill.list` 是按 Session 解析的执行目录。可安全传给浏览器的行只包含说明元数据和校验状态，不包含文件系统路径。有效 Skill 继续使用现有 `/<skill-name>` 调用约定。

用户显式调用在一个获准进入的步骤内保持幂等。当重叠的运行时作用域挂载了多个 `tool-skill` 消费器时，监听器会识别下游监听器已经提出的同名 `skill-invocation` 消息，不再追加另一条消息。因此 Session 日志对每个步骤中的每个 Skill 名只记录一条指令消息。

当前版本只支持目录安装和清单展示，不接收 ZIP 或 URL，也不覆盖或卸载目录。

## Alternatives considered

**继续只提供单文件安装器。** 不采用，因为它会静默丢弃 frontend-slides 等真实 Skill 所需的资源文件。

**通过通用渲染进程 RPC 发送选择后的源路径。** 不采用，因为渲染进程一旦被攻破就可能替换成任意可读路径。原生目录选择器和复制操作都留在高权限主进程。

**把目录上传到账户服务。** 不采用，因为本地 Workspace 执行和已安装 Skill 归设备所有；云端复制必须是独立、明确且受账户隔离的操作。

**在首个管理界面中提供覆盖或删除。** 不采用，因为这些操作可能破坏用户维护的资源。初始安装和清单功能只需报告冲突。

**要求每个组装后运行时只挂载一个 Skill 消费器。** 不采用，因为主机作用域与 Agent 作用域的分层取决于配置。有效组合发生重叠时，消费者本身必须保持调用语义。

## Consequences

聚焦的存储、IPC、preload、渲染进程、构建和已安装运行时证据由已实现的[功能规格](../../../../docs/specs/xiaowei/local-skill-directory-management.zh.md)关联。安装完整 frontend-slides 目录后，163 个普通文件保留在正式桌面运行时中。已安装运行时会通过 `skill.list` 发现该 Skill；即使本地配置挂载了重叠消费者，显式调用也只贡献一条持久化指令消息。

递归复制仍面对安装过程中可能变化的文件系统状态。导入器在读取文件前拒绝链接，使用 no-follow 文件句柄，限制工作量，校验暂存结果，串行化同名提交，并清理未完成的暂存目录。清单可见不等于 Skill 已在某个 Session 中生效，因此界面明确说明这一区别。ZIP 和 URL 导入、替换及删除仍不可用。
