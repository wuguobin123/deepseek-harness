# Agent Note: Office 文件上传与分析

Status: implemented

[English](2026-08-26-office-file-upload-and-analysis.md) | 中文

## Problem

对话输入区原本只接受图片，无法准入 PDF 或现代 Office 文件；已有表格制品路径可以渲染模型提供的数据行，但不能分析用户上传的工作簿。把浏览器原始字节或路径写入会话会违反持久附件规则，而接受模型提供的完整文件引用会允许跨会话读取。

## Decision

附件服务边界在部署可配置的数量和字节限制下准入 PDF、DOCX、XLSX 和 PPTX。 本地提供方校验声明的扩展名和媒体类型，拒绝不安全的 OOXML 压缩包，按照 SHA-256 身份保存原始字节，并返回带有服务端生成有界摘要的持久 `DocumentAttachmentRef`。prompt 端点把引用记录在现有 `user/message` 来源中，并把摘要追加为文本，因此所有模型可见输入仍可重建，无需增加新的内容块或会话事件。

`document_read` 只接受附件 ID，并在读取存储前从当前会话事件流解析完整引用。它通过游标提供有界的页面、章节、幻灯片或工作表单元。PDF 读取仅覆盖内嵌文本；读取器不执行 OCR、公式或宏，不访问链接，也不加载嵌入对象。

`sheet_analyze` 对 XLSX 文件执行同样的当前会话归属检查，解析共享字符串与缓存单元格值，并写入自包含的 `kind: 'sheet'` HTML 制品。页面包含语义化表格及内联 SVG 柱状图和饼图，现有制品结果卡与沙箱化右侧预览负责渲染持久字节。

浏览器在发送前把所选文件保存为临时草稿。可见文件选择器与文档级拖放目标接受图片及四种文档格式，保留混合批次顺序，并把 Office 文件渲染为带名称的文件块，而不是损坏的图片缩略图。

## Security and limits

OOXML 准入要求 ZIP 包含 `[Content_Types].xml`，拒绝路径穿越、加密包、宏、过大的解压字节和压缩比，并限制单元数、工作表行列数及提取字符数。旧版 DOC、XLS 和 PPT 不属于接受的媒体类型。

## Alternatives considered

**在会话中保存 base64 或本地路径。** 这会扩大持久日志、暴露机器本地信息并绕过内容寻址完整性检查，因此会话只保留不可变引用与有界文本。

**允许模型提交完整文档引用。** 结构有效的引用不能证明会话归属，因此工具只接收不透明 ID，并从当前会话解析权威引用。

**创建独立图表预览协议。** 现有表格制品已经提供持久化、会话关联、结果卡和沙箱 HTML 渲染，因此分析页面复用该路径，并把图表保留为内联 SVG。

## Consequences

用户可以上传并分析支持的文档格式，XLSX 分析能够作为同时包含两种所需图表的持久右侧页面打开。轻量读取器明确放弃 OCR、旧版 Office 兼容、公式计算、工作簿样式和完整 PDF 布局重建。验证覆盖格式拒绝、XLSX 共享字符串、跨会话拒绝、图片与文档混合提交、制品归属及图表 HTML 生成；打包后的 Electron 交互仍是独立的发布验收门。
