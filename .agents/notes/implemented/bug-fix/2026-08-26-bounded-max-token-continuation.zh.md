# Agent Note: 自动续写达到输出上限的小薇轮次

Status: implemented

[English](2026-08-26-bounded-max-token-continuation.md) | 中文

## Problem

小薇的 MiniMax 路由可能以原生结束原因 `length` 终止响应。适配器会正确地把它投影为 `max-tokens`，agent loop（智能体循环）也会关闭该轮次而不执行任何不完整的工具调用。生产证据显示，一个网站任务曾以这种方式连续结束四次；多个响应把可用输出都用于规划文字，却没有执行承诺的构建工具，因此用户每次截断后都必须发送“继续”。

提高请求中配置的上限无法消除提供方掌控的上限，把截断当作成功又会掩盖未完成工作。恢复机制必须保留每个受限轮次，在继续任务的同时避免无界 token 循环。它扩展既有的 [max-tokens 聊天提示](2026-08-12-max-tokens-turn-end-notice.zh.md)，后者仍负责持久化展示。

## Decision

`@deepseek-ai/dsh-max-token-continuation` 使用既有的 `agent/turn-stopping` 扩展点。关闭中的轮次若以最新 `max-tokens` finish 分片结束，守卫会排入一个独立、带插件来源的续写轮次。固定提示词要求模型从截断处继续，避免重复规划或只报告状态，保留已完成工作，并立即发出下一个必要工具调用。大型 HTML、文档、电子表格、表格和代码任务会优先通过可用的产物或文件工具完成并保存产物。

`maxContinuations` 限制连续自动轮次数；它不是正整数时会快速失败。守卫从持久会话事件重建序号与已处理轮次集合。当受限 `turn/end` 已持久化、而排队消息尚未被领取时，`agent/session-start { source: 'resume' }` 会重建一次续写；后续已有 `turn/start`、同一 `fromTurn` 已有续写或调用方工作已排队时都不会重复追加。正常完成或人类直接消息会重置续写链。小薇通过 `XIAOWEI_MAX_TOKEN_CONTINUATIONS` 配置该上限，默认值为八。

agent loop 保持不变。每个受限轮次仍保留 `turn/end { reason: { kind: 'max-tokens' } }`；新轮次及其 `{ cause, fromTurn, ordinal, limit }` 来源元数据都是普通的持久会话事件。不完整工具调用仍会被丢弃，下一次响应必须重新发出完整调用。会话客户端隐藏内部续写提示词，并在所属 max-tokens 提示上标注自动续写进度；不含这些元数据的旧日志继续显示人工续写指引。

## Alternatives considered

**提高 `maxTokens`。** 生产请求已经声明了高于提供方实际输出量的路由默认值，提供方上限仍然有效。

**在估算接近上限时提前中断。** 大多数提供方只有在终止 finish 分片中才提供可靠用量。提前中断流可能丢弃已经部分输出的工具调用，却无法证明提供方本来一定会触顶，因此续写只由精确的 `max-tokens` 原因触发。

**在同一轮次内继续。** agent loop 会让 `max-tokens` 在后续步骤中保持有效。独立轮次保留这一约定，也与既有人工恢复语义一致。

**重试相同的提供方请求。** 使用相同历史重试可能再次产生同样的长规划输出，也无法安全重建被截断的工具调用。

**不限制续写次数。** 模型若反复耗尽全部额度，会造成无界成本和延迟。

## Consequences

普通输出截断后，较长的小薇任务无需用户介入即可继续。transcript（文本记录）保留每个受限轮次，以及显示自动续写次数的收起提示。默认连续自动续写八次后，agent 会进入空闲，人工恢复仍然可用。每次续写都会增加一次模型请求和保留历史的 token 消耗。

聚焦的真实循环测试覆盖成功恢复、硬上限、正常完成、无效配置、重启恢复、重复恢复事件与调用方优先级。人工编写的 ACP 快照在参数中途截断工具调用，证明不完整调用不会执行，系统会自动开启新轮次、重新发出完整调用、写入文件，并在一次客户端提示词生命周期内完成。
